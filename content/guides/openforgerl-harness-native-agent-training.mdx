OpenForgeRL은 클로드 코드, 코덱스, 오픈클로 같은 복잡한 에이전트 하네스를 수정 없이 그대로 강화학습시키는 오픈소스 프레임워크다. 하네스의 모델 호출을 가로채는 경량 프록시와, 각 롤아웃을 독립 컨테이너에서 굴리는 쿠버네티스 오케스트레이터로 훈련과 추론을 분리했다. 수백~수천 개 태스크만으로 GUI 에이전트가 WebVoyager 72.3점, OSWorld-Verified 37.7점을 기록해 동급 오픈소스 기준선을 대부분의 벤치마크에서 앞질렀다.

| 항목 | 수치 |
| --- | --- |
| WebVoyager 점수 | 72.3 |
| OSWorld-Verified 점수 | 37.7 |
| Online-Mind2Web 점수 | 63.0 |
| 학습에 쓴 태스크 수 | 수백~수천 건 |

## 1. OpenForgeRL은 무엇을 하는 프레임워크인가?

요즘 AI 에이전트는 클로드 코드, 코덱스, 오픈클로처럼 정교한 추론 하네스 위에서 움직인다. 멀티턴 추론과 도구 사용, 외부 시스템 접근까지 이 하네스가 관리한다. 문제는 이런 하네스가 상태를 유지하는 다중 프로세스 구조라, 기존 오픈소스 SFT·RL 스택으로는 표현하기 어렵다는 점이다. 그 결과 연구자들은 실제 배포 환경과는 다른 단순화된 환경에서 에이전트를 훈련시켜 왔다.

OpenForgeRL은 이 간극을 메우려는 오픈소스 프레임워크다. 다양한 하네스를, 다양한 환경에서, 있는 그대로 종단간(end-to-end) 학습시키는 것이 목표다. 연구진은 이 프레임워크를 툴·클로 기반 에이전트부터 멀티모달 GUI 브라우저·컴퓨터 사용 에이전트까지 폭넓은 하네스와 환경에서 검증했다.

## 2. 기존 오픈소스 기준선과 비교하면 얼마나 다른가?

OpenForgeRL로 학습시킨 두 계열의 에이전트는 여러 벤치마크에서 다음 점수를 기록했다.

| 에이전트 유형 | 벤치마크 | 점수 |
| --- | --- | --- |
| OpenForgeClaw | ClawEval (pass@3) | 55.9 |
| OpenForgeClaw | QwenClawBench | 33.7 |
| OpenForgeGUI | OSWorld-Verified | 37.7 |
| OpenForgeGUI | Online-Mind2Web | 63.0 |
| OpenForgeGUI | WebVoyager | 72.3 |

두 계열 모두 비슷한 크기의 오픈소스 기준선을 거의 모든 벤치마크에서 앞섰다. GUI 계열은 한발 더 나아가, 자신보다 몇 배 큰 모델과 맞먹거나 넘어서는 결과를 냈다.

> **요약**: 비슷한 크기의 오픈소스 기준선은 거의 다 앞섰고, GUI 환경에서는 몇 배 큰 모델과도 맞먹거나 넘어섰다.

## 3. 하네스를 그대로 강화학습에 걸려면 어떻게 하나?

핵심은 훈련과 추론을 분리하는 구조다. 경량 프록시가 하네스의 모델 호출을 그대로 서빙하면서 동시에 이를 표준 RL 코드베이스(예: veRL)가 쓸 수 있는 학습 데이터로 기록한다. 여기에 쿠버네티스 오케스트레이터가 붙어, 각 롤아웃을 독립된 원격 컨테이너에서 실행한다.

이 조합 덕분에 연구자는 하네스 내부 코드를 바꾸지 않고도 실제 배포에 쓰는 바로 그 하네스와 환경에서 에이전트를 훈련·분석·개선할 수 있다. 임의의 하네스를 임의의 환경에서, 규모를 키워가며 학습시킬 수 있다는 뜻이다.

## 4. 실전에 어떤 의미가 있나 — 무엇을 주의해야 하나?

연구진은 하네스 선택(제로클로, 오픈클로, 코덱스 등)과 강화학습이 에이전트 행동을 어떻게 바꾸는지도 분석했다. 일부 하네스는 다른 하네스보다 학습 난도가 눈에 띄게 높았다. 강화학습은 자기검증, 도구 커버리지, 다단계 계획 완수 같은 에이전트 신뢰성 지표를 끌어올렸다.

다만 모든 게 좋아진 것은 아니다. 오류 복구 같은 핵심 능력은 강화학습 이후에도 여전히 약한 채로 남았다. 하네스 기반 에이전트를 실제로 배포하려는 팀이라면, 벤치마크 점수만 보지 말고 오류 발생 시 복구 시나리오를 별도로 점검할 필요가 있다.

> **주의**: 오류 복구 능력은 강화학습으로도 크게 개선되지 않았다 — 배포 전 반드시 별도로 시험해야 하는 지점이다.

- **Q. 어떤 하네스에서 검증됐나?**
  - **A.** 클로드 코드, 코덱스, 오픈클로, 제로클로 등 툴·클로 기반 에이전트와 멀티모달 GUI 브라우저·컴퓨터 사용 에이전트에서 검증했다.
- **Q. 학습에 얼마나 많은 데이터가 필요한가?**
  - **A.** 수백에서 수천 개 태스크 수준으로, 대규모 데이터 없이도 동급 오픈소스 기준선을 대부분 앞서는 성능을 냈다.

## 마무리 — agenwiki의 한줄평

에이전트 연구가 단순화된 샌드박스를 벗어나 실제 배포 하네스 그대로 학습하는 방향으로 옮겨가고 있음을 보여주는 사례다. 다만 오류 복구력이 여전히 약하다는 점은, 벤치마크 점수와 실전 신뢰성 사이에 남은 간극을 그대로 드러낸다.
